# JSLib.d.ts — a generated standard library for `-jslib` builds

Date: 2026-08-06
Status: approved, ready for planning

## Problem

`tsc-lua` type-checks user code against TypeScript's bundled `lib.es5.d.ts`, even when
compiling for the jslib runtime. The two disagree about shape, and the emitter has to
paper over the difference by hand.

`lib.es5.d.ts` declares:

```ts
declare var Math: Math;
interface Math { floor(x: number): number; }
```

`floor` is an *instance* member, so the emitter classifies `Math.floor(x)` as a self call
and emits `Math:floor(x)`. The jslib runtime, however, defines `Math` as a plain table of
functions taking no `self` (`experiments/jslib/JS.lua:1670`), generated from
`experiments/jslib/Math.ts`, where the members are `static`. `Math:floor(x)` would pass the
`Math` table as `op` and shift every argument by one.

The current workaround is a hardcoded special case in `src/emitterlua.ts:3420`:

```ts
else if (this.isCallOfMemberWithoutSelf(node) || (<any>node.expression).__return_type === 'Math') {
    thisCall = false;
}
```

This fixes `Math` and nothing else. Any other place where jslib's shape diverges from
`lib.es5.d.ts` is either already wrong or one edit away from being wrong.

## Goal

Generate `JSLib.d.ts` from `experiments/jslib/*.ts` and compile against it, with
`noLib: true`, whenever the jsLib mode is active. The declarations then describe the
runtime that actually exists, `isCallOfMemberWithoutSelf` reaches the right answer on its
own, and the `Math` special case is deleted.

## Decisions

| Question | Decision |
| --- | --- |
| How is `JSLib.d.ts` produced? | Generated by a script, checked into the repo. Regenerated only when jslib sources change. |
| Generator mechanism | TypeScript Compiler API with a type checker (`ts.Program` + `ts.createPrinter`). |
| Does it replace or augment `lib.es5.d.ts`? | Replaces it — `noLib: true`. Augmenting is impossible: `declare class Math` collides with lib's `declare var Math: Math`. |
| Globals jslib does not implement | A small hand-maintained prelude, limited to what TypeScript structurally demands. |
| jslib's Helper/boxed split | Merged into one `declare class` per global. |
| Scope | Wire it up, remove the `Math` hack, and add regression tests. |

## Architecture

Four components, each with one job.

### 1. `experiments/jslib/core.prelude.d.ts` (hand-maintained, ~40 lines)

The globals TypeScript structurally demands that jslib does not implement: `Boolean`,
`Function`, `IArguments`, `Symbol`, `IteratorResult` / `Iterable` / `IterableIterator`,
`RegExpMatchArray` / `RegExpExecArray`, plus `declare var NaN: number` and
`declare var Infinity: number` (`Common.ts` assigns `Infinity`).

It deliberately does **not** declare Lua globals (`math`, `table`, `tostring`, …). Those
are already handled at emission time by `unresolvedFilter` in `src/resolvers.ts:304-316`,
and user code declares its own today. Excluding them keeps this change confined to the JS
standard library.

It is co-located with the jslib sources but is not part of their build: it stays out of
`experiments/jslib/tsconfig.json`'s `include`, and the generator reads it as plain text
from `jslibDir` and prepends it to the output.

### 2. `src/jslibdts.ts` — the generator

Exports `generateJsLibDts(jslibDir: string): string`. It builds a `ts.Program` over the
files listed in `experiments/jslib/tsconfig.json`'s `include`, applies the transformation
rules below, and returns the printed text with the prelude prepended. A pure function of
the directory, with no I/O side effects, so it is directly unit-testable.

### 3. `scripts/build-jslib-dts.ts` and `npm run build-jslib-dts`

A thin CLI wrapper: call the generator, write `lib/JSLib.d.ts` at the repo root.
`prepublish_npm.cmd` gains a `copy lib\JSLib.d.ts packages\tsc-lua\` line so the file ships
beside `JS.lua`.

### 4. `Helpers.isJsLib()` and `Helpers.findJsLibDts()`

The jsLib predicate is currently duplicated in `src/emitterlua.ts:64-71` and
`src/emitter.ts:86`, and it runs *after* the program has already been built. It moves to
`Helpers` so `src/compiler.ts` can consult it at program-creation time; both emitters then
call the same helper.

`findJsLibDts()` walks up from `__dirname` looking for `JSLib.d.ts` / `lib/JSLib.d.ts`,
the same technique `Run.getLuaInterpreter` (`src/compiler.ts:68-84`) already uses to find
`__dist`. That resolves to `packages/tsc-lua/JSLib.d.ts` when installed and
`lib/JSLib.d.ts` in the repo.

### Data flow

```text
main.ts
  → Run.run
    → compileWithConfig / compileSources
      → Helpers.isJsLib(options, cmdLineOptions)
        → if true: options.noLib = true, rootNames = [JSLib.d.ts, ...fileNames]
      → ts.createProgram
        → checker sees `declare class Math { static floor(...) }`
          → isCallOfMemberWithoutSelf returns true unaided
            → emitter emits `Math.floor(x)` with no special case
```

## Generation rules

**R1 — Flatten modules.** Every `export class C` inside `module JS` / `module TS` becomes a
top-level `declare class C`. This mirrors the emitter, which lowers such a class to a
*global* of the class's own name and only then aliases it (`TS.Math = Math`,
`experiments/jslib/JS.lua:1752`).

**R2 — Merge Helpers, by an explicit map.** The map is `{ StringHelper → String,
NumberHelper → Number }` — two entries, no name-based magic. For each static on the helper:

- first parameter literally named `this` (`static charCodeAt(this: string, index: number)`)
  → emitted as an **instance** member of the target, with the `this` parameter dropped.
  This is what makes `"abc".charCodeAt(0)` type-check, which in turn is what fires the
  existing `StringHelper` rewrite in `src/preprocessorlua.ts:327-336`.
- otherwise (`static fromCharCode(code)`) → a **static** member of the target.

On a name collision the **helper wins**. Nine members overlap (`replace`, `charCodeAt`,
`substr`, `substring`, `indexOf`, `split`, `slice`, `toLowerCase`, `toUpperCase`, plus
`Number.toString`), and they differ in return type: the boxed class returns `String`, the
helper returns `string`. The merged type is above all the apparent type of the *primitive*,
and primitive calls are rewritten to the helper at emit time, so the helper's `string` is
the accurate answer — and `string` rather than `String` is what keeps
`TypeInfo.isTypeOfNode(…, 'string')` firing on the result. Static and instance names live in
separate namespaces, so `fromCharCode` never collides with anything.

Helper classes are also still emitted as their own globals, because that is what they are
at runtime — subject to R3 and R4 like every other emitted class, and keeping their `this`
parameters as written. `ArrayHelper` is not in the map: its statics take `_this`, not
`this`, and nothing outside jslib calls them.

**R3 — Drop what is not API.** `private` and `protected` members, and the Lua metamethod
members (`__tostring`, `__index`, `__newindex`, `__call`, `__len`, `__lt`, `__le`, `__add`,
`__sub`, `__mul`, `__div`, `__unm`, `__concat`, `__eq`).

Known consequence: `stack` is `private` in `experiments/jslib/Error.ts`, so `err.stack`
will not type-check. That is accurate to jslib as written. If it should type-check, the fix
belongs in `Error.ts` — make the field public — not in the generator.

**R4 — Strip bodies, keep types.** Bodies and decorators are removed. A member without a
type annotation gets the checker's inferred type printed (`static E = 2.718…` becomes
`static E: number`). Optionality is preserved; parameter defaults are dropped.

**R4a — Accessors become properties.** `get length()` / `set length()` are emitted as a
single property per *name*: a get/set pair or a lone setter is writable, a lone getter is
`readonly`. The dot-versus-self decision never involves properties, so nothing is lost, and
a property is the honest shape for a value that is read and written. Without this rule
`Array.length` (`Array.ts:173-177`) and `String.length` (`String.ts:227`) disappear
entirely, and `.length` stops type-checking.

**R5 — Top-level declarations.** A top-level `function` in a jslib file becomes a
`declare function` — this is how `Common.ts` contributes `parseInt`, `parseFloat`, `isNaN`,
`isFinite`, and `decodeURIComponent`. A top-level `declare var X` that the same file
*assigns* becomes a typed global (`Console.ts` yields `declare var console: Console`). An
ambient `declare var` that is never assigned (`math`, `table`, `tostring`, `os`, `io`,
`debug`, …) is dropped; those are Lua natives, not JS API.

**R6 — Exclusions.** `module JS`'s `export class undefined` is skipped, because
`declare class undefined` collides with the intrinsic. Non-exported module members
(`String.ts`'s `type FuncString`) are skipped.

**R6a — Type aliases come along.** An alias declared in a jslib file is collected and
flattened exactly like a class and emitted as `declare type X = …;`, ahead of that file's
classes. Annotated member types are kept verbatim from the source, so `String.replace`
carries `string | FuncString` — and without the alias the generated file does not type-check
on its own. Unlike classes, an alias need not be exported to be collected: `FuncString` in
`String.ts` is not.

**R7 — Deterministic output.** Emission follows the `include` order in
`experiments/jslib/tsconfig.json`, with classes in source order, so regeneration is
byte-identical and diffs stay readable. A header comment marks the file as generated and
names `npm run build-jslib-dts`.

## Wiring

`Helpers.isJsLib(options, cmdLineOptions)` carries the predicate over verbatim from
`src/emitterlua.ts:64-71`, guarding `cmdLineOptions` against `undefined` (a case
`src/emitter.ts:86` can reach).

In `src/compiler.ts`:

- `compileSources` and `compileWithConfig`: when jsLib is active, set `options.noLib = true`
  and build the program with `rootNames: [jsLibDts, ...fileNames]`. `JSLib.d.ts` goes into
  **rootNames only, never into the `sources` array** — `generateBinary` filters `.d.ts` out
  of the multi-file path and matches against `sources` in the singleModule path, so keeping
  it out of `sources` is what prevents it being emitted as `JSLib.lua`.
- Watch mode: `ts.createWatchCompilerHost(configPath, …)` offers no way to add a root file.
  When jsLib is active, the watch path switches to the `rootFiles` overload with
  `[jsLibDts, ...parsedCommandLine.fileNames]` and `{...options, noLib: true}`.
  Trade-off, accepted: under `-jslib -watch`, `tsconfig.json` itself is no longer watched.
  Source watching is unaffected, and non-jslib watch keeps the existing configPath overload
  untouched.
- `Run.test` gets the same injection, so `{ jslib: true }` specs exercise the real path.

In the emitters:

- `src/emitterlua.ts:64-71` and `src/emitter.ts:86` both become
  `this.jsLib = Helpers.isJsLib(options, cmdLineOptions);`.
- `src/emitterlua.ts:3420` loses `|| (<any>node.expression).__return_type === 'Math'` and
  its trailing comment, leaving the plain `isCallOfMemberWithoutSelf(node)` test.

## Error handling

`findJsLibDts()` returning nothing throws
`-jslib requires JSLib.d.ts; run 'npm run build-jslib-dts'`. Failing loudly matters here:
silently falling back to `lib.es5.d.ts` reproduces exactly the bug being fixed, in a form
nobody would notice until the generated Lua misbehaves at runtime.

The generator throws by name if a class named in the merge map is absent from the sources,
rather than emitting a half-populated `String`.

## Testing

1. `Run.test`'s emit half is extracted into `Run.testEmit(sources, cmdLineOptions): string`,
   which returns the generated Lua text; `Run.test` then calls it. No duplication, and it
   makes emit-shape assertions possible.
2. `spec/jslib.spec.ts` — two emit-level assertions under `{ jslib: true }`:
   - `Math.floor(1.5)` must emit `Math.floor(`, never `Math:floor(`. This is the guard that
     lets the special case be deleted; it passes today only *because* of the special case.
   - `String.fromCharCode(65)` must emit `String.fromCharCode(`, never
     `String:fromCharCode(`. This one is **broken today**: the special case only ever
     covered `Math`, so `lib.es5.d.ts`'s `declare var String: StringConstructor` resolves
     `fromCharCode` to a `MethodSignature`, `isStaticMethod` rejects it, and a self call is
     emitted. It is the honest failing test that JSLib.d.ts fixes.

   Both are asserted at emit level rather than behaviourally, because `Run.test` spawns Lua
   without `JS.lua` on the path — which is why `spec/instanceof.spec.ts` declares its own
   `class Number {}` locally.
3. `spec/jslibdts.spec.ts` — generator unit test. The output contains `declare class Math`
   with `static floor`; `String` has an instance `charCodeAt` **and** a static
   `fromCharCode`; `class undefined` and `declare var math` are absent.
4. The existing 20 spec files stay green. The non-jslib path is untouched by design.
5. Manual check: rebuild `experiments/BABYLON` (a real `-jslib` consumer, via
   `build_bs.bat`) and diff the emitted `.lua` for unintended self-call changes.

## Out of scope

Deliberately deferred; revisit only if a concrete need appears.

- Declaring Lua natives (`math`, `table`, `os`, …) in `JSLib.d.ts`.
- Back-filling `lib.es5.d.ts` APIs that jslib does not implement (`Promise`, generators,
  `Intl`, the `Symbol.iterator` machinery). Declaring them would advertise APIs absent at
  runtime.
- Making `Error.stack` public in `experiments/jslib/Error.ts`.
- Watching `tsconfig.json` under `-jslib -watch`.
